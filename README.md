# Bluetooth-приёмник для Volumio

Позволяет подключить телефон к Volumio по Bluetooth и слушать через него — то
есть использовать плеер как обычную колонку (профиль A2DP Sink).

Проверено 26.09.2026 на Volumio 4.119, Raspberry Pi 4, ЦАП IQaudIO DAC Plus.

## Главное: ничего не заблокировано

Принято считать, что Bluetooth-приём в бесплатной версии Volumio закрыт и его
нужно как-то обходить. Это не так. Проверка стокового образа показала, что
весь стек на месте, запущен и настроен именно как приёмник:

| что | состояние в стоковом образе |
|---|---|
| BlueZ | `5.83-1volumio1` |
| bluez-alsa | `4.3.1volumio1`, служба `bluealsa.service` **запущена** |
| Команда запуска | `/usr/bin/bluealsa -S -p a2dp-source -p **a2dp-sink**` |
| Точки в BlueZ | `/org/bluez/hci0/A2DP/SBC/**sink**/1`, `/sink/2` зарегистрированы |
| UUID адаптера | `0000110b` — **A2DP AudioSink**, объявлен в эфир |
| Класс устройства | `0x0c041c` — Audio/Video, Portable Audio, Rendering |
| `/etc/bluetooth/main.conf` | `Enable=Source,Sink`, `AlwaysPairable = true`, таймауты 0 |
| `bluealsa-aplay` | есть в `/usr/bin`, работает от пользователя `volumio` |

Адаптер уже объявляет себя колонкой, телефон уже может с ним сопрячься.
Упоминание Bluetooth во всём бэкенде Volumio нашлось **ровно одно** — в
`pluginmanager.js`; плагина аудио-приёмника в бесплатном образе просто нет.

Не хватает единственного звена: процесса, который возьмёт входящий поток и
отдаст его на звуковую карту. Премиум продаёт интерфейс сопряжения и эту
обвязку, а не саму возможность. Поэтому здесь нечего взламывать — и ничего не
взламывается: используется свободный софт, уже установленный производителем.

## Подводный камень

Запустить `bluealsa-aplay` без параметров недостаточно. По умолчанию он
цепляется к ALSA-микшеру с именем `default`, который на Volumio уходит в
PulseAudio и отваливается по таймауту:

```
ALSA lib pulse.c:242:(pulse_connect) PulseAudio: Unable to connect: Timeout
bluealsa-aplay: W: Couldn't open ALSA mixer: Attach mixer: Connection refused
bluealsa-aplay: D: Exiting IO worker
```

Поток при этом открывается и тут же умирает. Лечится явным указанием
аппаратного микшера карты — `install.sh` читает имя карты и микшера прямо из
настроек Volumio, так что подходит для любого ЦАПа.

## Состав

Всё, что попадает в систему, лежит здесь отдельными файлами — установщик их
только раскладывает, ничего не генерируя на ходу:

| файл в репозитории | куда ставится | что это |
|---|---|---|
| `bin/bt-receiver` | `/usr/local/bin/bt-receiver` | запускает `bluealsa-aplay` с правильными параметрами |
| `default/bt-receiver` | `/etc/default/bt-receiver` | настройки: карта и микшер |
| `systemd/bt-receiver.service` | `/etc/systemd/system/` | юнит автозапуска |
| `install.sh` | — | раскладывает три файла выше |
| `uninstall.sh` | — | убирает их |
| `diagnose.sh` | — | показывает состояние стека, root не нужен |

## Установка

```bash
sudo bash install.sh
```

Больше ничего в системе не трогается. Существующий `/etc/default/bt-receiver`
установщик не перезаписывает.

Удалить (настройки останутся; `--purge` уберёт и их):

```bash
sudo bash uninstall.sh
```

Посмотреть состояние всего, от чего это зависит, без root:

```bash
bash diagnose.sh
```

## Настройка

По умолчанию `/etc/default/bt-receiver` пуст, и тогда карта с микшером берутся
**из настроек самого Volumio** при каждом запуске — поменяли ЦАП в интерфейсе,
приёмник подхватит. Заполнять эти переменные нужно, только если звук с телефона
должен идти не туда, куда играет Volumio.

## Сопряжение

Телефон видит устройство под именем из `bluetoothctl show` (по умолчанию
`Volumio`). Если адаптер не виден, включить видимость можно без root:

```bash
bluetoothctl
[bluetooth]# agent on
[bluetooth]# default-agent
[bluetooth]# discoverable on
[bluetooth]# pairable on
```

После сопряжения имеет смысл пометить телефон доверенным, чтобы он
переподключался сам: `trust <MAC>`.

## Совместная работа с Volumio

Звуковая карта у MPD монопольная, поэтому:

- телефон играет → `bluealsa-aplay` занимает выход;
- телефон на паузе → выход освобождается, Volumio играет как обычно.

Это проверено: при паузе `/dev/snd/pcmC4D0p` освобождается, в логе появляется
`BT device marked as inactive`, сам процесс остаётся жить и ждёт следующий
поток. Обратное направление — старт потока с телефона, когда Volumio уже
играет, — **не проверялось**; ожидаемо поток не пробьётся, пока MPD держит
устройство.

## Что переживает обновление

Юнит лежит в `/etc/systemd/system` и при обновлении образа Volumio исчезнет.
Раздел `/data` обновление переживает, поэтому проще всего положить этот
репозиторий туда — переустановка после обновления сведётся к повторному
запуску `install.sh`.

## Оговорка

Приёмник воспроизводит функциональность, которую Volumio продаёт в подписке.
Технически здесь не обходится никакая защита: используется GPL-софт, уже
установленный в образе, и штатные средства systemd. Но официальной поддержки у
такой конфигурации нет, и решение о её использовании — ваше.
